Inside a cell ID

One 64-bit integer holds the whole thing: which planet, which cell, which layer. The chunk ID isn't a separate number — it's the front of this one, and the chunk level isn't a field at all. Drag it and watch: the dashed line moves, and not one bit does.

The encoding is deliberately sparse, in three places at once: only 20 of 32 face codes exist, only 3 of 4 corner codes exist, and a vertex is a corner of six triangles so five of its six names are thrown away. Multiply those and 7.81% of the code space is used — 3.68 bits spent. What it buys is addressing that's pure shifts and masks, with no lookup tables anywhere.
An older version of this page drew the layout as face · path · q · r, with the chunk level deciding how many bits went to the path and how many to q,r. That layout keeps a fixed width, which is what it was drawn to show — but the number changes when you move the cut, so the chunk level would be baked into every ID ever written to disk. Path digits name triangles, and a cell is a vertex: hence the 2-bit corner field above, and hence the path running all the way down.
